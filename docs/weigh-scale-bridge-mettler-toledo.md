## 2. 桥接主路径：RS232 读重量（优先）

秤端 RS232 串口是该系列标配，桥接以 RS232 重量读取为主路径：

```text
梅特勒托利多秤（只称重）
  → 店内网关（联网主机上的串口读数程序，RS232 直连）
  → POST /ext/hardware/webhook/weigh（HARDWARE_SECRET Bearer <redacted>）
  → hardware_event（event_type='weigh'，与 pick 同记一本账）
  → 柜台页 /shop/counter 轮询最新读数 → 店员点选确认 → 计价行项进单据
```

约定（沿用 `docs/weigh-scale-contract.md` §2–§3，一字不动）：

- 鉴权：`Authorization: Bearer <redacted>`。
- 幂等：网关生成唯一 `message_id`（`scale-<uuid>`），重发返回
  `{status: "duplicate"}`，不重复计账；断网本地缓存、恢复后按 `message_id`
  幂等补发。
- 计价在主干侧完成，网关不算钱：单价取批次 `retail_price_cents`（缺失退变体
  `reference_price_cents`），取不到 → 422，不写账；基准解析不出 → 422，不写账。
  **无价 422，绝不编价格。**
- 重量范围：整数克，1..15000（秤量程 15KG），超限 422 拒收。

串口侧现状：`app/scale.py` 已有托利多连续输出解析（`S 0.000 kg` /
`ST 0.000 kg`，见 `parse_scale_line`）与稳定判定、去皮、清零；网关职责是
读串口 → 稳定后取值 → 克换算 → 生成 `message_id` → POST 上报。

**写驱动前须卖家书面确认（未确认前不写驱动）：**

1. 串口参数（波特率/数据位/校验/停止位；常见 9600、8 数据位、无校验、1 停止位，
   以卖家文档为准）与帧格式（含稳定位、单位、去皮标志）。
2. 重量数据出口形式：RS232 直出，还是须经秤自带软件/Windows 侧 SDK/虚拟串口。
3. 称重模块与主板之间是否还有厂商私有协议。

## 3. 打印机与顶部摄像头：分两种情况，别默认能用

| 情况 | 判定 | Hemal 能否直接用 |
| --- | --- | --- |
| (a) PC 平台/开放系统 | 铭牌型号属开放平台机型，系统可装软件/驱动，背面接口含可用 USB/串口/RJ45 | 可直连：打印机走驱动/串口，摄像头走 UVC/RTSP 标准取流（网关契约见 `docs/weigh-scale-contract.md` §6） |
| (b) 封闭系统 | 只能走秤自带软件，无开放驱动/取流口 | 接不了：摄像头改外接通用摄像头（UVC/RTSP），打印机另配；秤只当哑巴秤（只称重） |

判定方法（到货后逐项核对，不猜）：

1. 看型号：读铭牌上的完整型号，对照本节公开资料确认属于哪一类。
2. 看系统：开机进系统，看是开放平台（可装软件/驱动、有桌面/设置入口），
   还是封闭一体机（只能用自带称重软件）。
3. 看背面接口照片：RS232 口在不在、USB 口是 Host 还是仅 Device、RJ45 通不通、
   打印机是内置串口/ USB 还是秤内私有总线。

买之前向卖家要的东西（Soffy 负责）：型号、通电视频、背面接口照片。

## 5. 到货后联调清单（以这台为准）

1. 核对型号：铭牌型号与卖家说法一致，确认属 §2/§3 的哪一种。
2. 通电验屏：开机有画面，称重屏显示正常；查“网络断开”原因（网线/RJ45/店内网）。
3. 量串口出数：RS232 接网关主机，读数程序收到稳定重量帧，克数与屏显一致。
4. 打印机出纸：按 §3 判定直连或另配；直连则打一张测试小票。
5. 摄像头取流：按 §3 判定直连（UVC/RTSP 取流成功）或改外接通用摄像头。
6. 全链路：称重 → webhook → 柜台单据 → 计价 → 现金/储值结算，跑一单真账。
7. 断网补发：断网称重一次，恢复后按 `message_id` 幂等补发，不重复计账。
