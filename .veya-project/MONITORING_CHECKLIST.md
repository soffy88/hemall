# hemal 监控任务清单

> 执行者：监控管理 agent。所有结果写入监控平台或项目 issue；禁止把 secret 写入日志。

## 每次执行前

- [ ] 读取 `PROJECT_STATE.md`，确认仓库、环境和命令仍有效。
- [ ] 检查上次任务是否失败、是否存在未关闭 incident。
- [ ] 记录执行时间、commit / release、检查版本和结论。

## 每日检查

### 代码健康

- [ ] 默认分支同步状态、最近失败构建和未合并高风险变更。
- [ ] 执行项目定义的 format / lint / typecheck；当前尚未配置，保持 `pending`，不得伪报成功。
- [ ] 检查 TODO/FIXME、构建时长、失败率和质量门禁趋势。

### 依赖安全

- [ ] 执行锁文件一致性与依赖漏洞扫描。
- [ ] 对 Critical/High 漏洞创建或更新 issue，确认是否已有修复版本。
- [ ] 检查过期依赖、镜像基础层和 secret 扫描结果。

### 部署状态

- [ ] 检查 staging / production 发布状态、实例数和最近一次发布。
- [ ] 请求健康端点，验证 HTTP 状态、响应时间和关键依赖连通性。
- [ ] 检查错误率、5xx、重启、资源耗尽和证书有效期。

### 测试覆盖

- [ ] 执行快速回归测试和覆盖率采集。
- [ ] 对比主分支基线；覆盖率下降超过项目阈值则告警。
- [ ] 记录 flaky test，并避免因重试掩盖真实失败。

## 每周检查

- [ ] 汇总过去 7 天构建、部署、故障、恢复时间和告警噪声。
- [ ] 做一次完整测试 / 安全扫描 / 依赖升级评估。
- [ ] 审核备份、恢复演练、回滚路径和监控盲点。
- [ ] 更新 `PROJECT_STATE.md` 的架构、部署、负责人和风险信息。
- [ ] 关闭已验证的告警，给未解决风险补 owner、优先级和截止时间。

## 判定规则

- 任意检查因缺少配置无法执行：标记 `BLOCKED`，创建配置缺口 issue，不标记为通过。
- Critical 漏洞、生产健康检查失败、持续 5xx 或数据完整性风险：进入 `P1` 响应。
- High 漏洞、部署回滚、覆盖率越过门槛：进入 `P2` 响应。
- 其余可计划问题：进入 `P3`，纳入周报和 backlog。
